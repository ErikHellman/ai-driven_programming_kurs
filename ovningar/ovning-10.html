⚡ Publicera med Supabase

Ta appen från övning 8 ut på nätet, så att alla i fikagänget kan använda den i sina mobiler. Datan flyttar till Supabase, och frontenden publiceras på GitHub Pages. Du skapar konto, installerar Supabase CLI och loggar in själv. Sedan låter du agenten sköta resten.

Syftet med övningen: att se hur en fullstack-app kan köra på nätet utan att du har en egen server, och att låta agenten använda ett nytt verktyg åt dig.

Innan du börjar: du behöver en app med egen backend, till exempel från övning 8, som fungerar på din dator och ligger på GitHub.

  1. 🧩 Vad är Supabase?

    Supabase är en backend som tjänst. Du får färdigt det som din Express-server och SQLite-fil gjorde i övning 8, fast på nätet:

    • En databas: Postgres, en av världens vanligaste databaser. Samma tabeller och samma SQL som i del 2.
    • Ett REST-API: Supabase gör automatiskt ett API av varje tabell. Tabellen fikor får adressen /rest/v1/fikor, och du använder GET, POST och DELETE precis som förut.
    • Regler i stället för kontroller: det som din backend kontrollerade blir regler i databasen. Row Level Security bestämmer vem som får läsa, lägga till och ta bort.
    • Inloggning: finns färdigt om du vill bygga vidare.

    Frontenden är fortfarande bara filer, så den kan ligga kvar på GitHub Pages och prata direkt med Supabase. Din egen Express-server behövs inte längre när appen är publicerad.

    PlanPrisDet här ingår
    Free0 dollar2 aktiva projekt, 500 MB databas per projekt, 1 GB filer, 50 000 inloggade användare i månaden och 5 GB trafik.
    Profrån 25 dollar i månaden, drygt 250 kronorStörre gränser, projekt som aldrig pausas och dagliga säkerhetskopior. Fler projekt kostar från 10 dollar i månaden.
    • Gratis räcker långt: en fikalista använder en bråkdel av gränserna.
    • Projektet pausas: ett gratisprojekt som inte används på en vecka pausas. Datan finns kvar, och du startar projektet igen med en knapp på supabase.com.
    • Pro har ett kostnadstak som är påslaget från början, så att du inte betalar för mer än det som ingår. Du behöver inte Pro för den här övningen.

    Priserna ändras. Siffrorna ovan gällde i november 2026. Kolla alltid Supabases prissida innan du väljer en plan som kostar.

  3. 🔐 Skapa konto och ett projekt, själv

    Det här gör du själv, inte agenten. Kontot är ditt och inloggningen ska aldrig gå via chatten.

    1. Gå till supabase.com/dashboard/sign-up och skapa ett konto. Spara inloggningen i lösenordshanteraren.
    2. Klicka på New project. Ge det ett namn, till exempel fikalistan, och välj en region i Europa, gärna Stockholm om den finns.
    3. Supabase ber om ett lösenord till databasen. Låt den skapa ett starkt lösenord och spara det i lösenordshanteraren. Det skriver du aldrig i chatten.
    4. Välj planen Free och vänta någon minut medan projektet startar.

    Projektets adress ser ut så här: https://abcdefghijkl.supabase.co. Bokstäverna i början är projektets id, som agenten behöver senare.

  4. 📦 Installera Supabase CLI

    Supabase CLI är Supabases kommandoradsverktyg, ungefär som gh är GitHubs. Kommandot heter supabase.

    Vi gissade ditt operativsystem. Byt om det blev fel.

    På Windows installeras det med Scoop, ett program som installerar andra program. Har du inte Scoop, installera det först i PowerShell:

    PowerShell · Scoop 
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Invoke-RestMethod -Uri https://get.scoop.sh | Invoke-Expression

    Installera sedan Supabase CLI:

    PowerShell 
    scoop bucket add supabase https://github.com/supabase/scoop-bucket.git
scoop install supabase
    Terminal 
    brew install supabase/tap/supabase
    Terminal 
    brew install supabase/tap/supabase

    Har du inte Homebrew finns färdiga paket under Releases på github.com/supabase/cli.

    Stäng terminalen, öppna en ny och kolla att det fungerade:

    Alla system 
    supabase --version
    Vill du inte installera något globalt?

    Supabase CLI kan också installeras i projektet med npm install -D supabase. Då skriver du npx supabase i stället för supabase i alla kommandon, och säger det till agenten.

  5. 🔑 Logga in, själv

    Alla system 
    supabase login

    Webbläsaren öppnas och du godkänner inloggningen. CLI:t sparar en nyckel på din dator. Nu kan agenten använda supabase åt dig, eftersom den kör kommandon på samma dator och med samma inloggning som du. Precis som med gh.

    Kolla att det fungerade. Du ska se ditt projekt i listan:

    Alla system 
    supabase projects list

  6. 🤖 Låt agenten flytta datan

    Öppna projektet i Claude- eller ChatGPT-appen och starta en ny session. Byt ut projektets id i prompten. Den här fungerar för appen från övning 8:

    Prompt 
    Jag vill publicera den här appen med Supabase som backend och GitHub Pages för frontenden. Jag har skapat ett Supabase-projekt med id abcdefghijkl, installerat Supabase CLI och loggat in med supabase login. Kör supabase projects list först för att kontrollera det.

Krav:
- Flytta databasen till Supabase. Skapa tabellerna som en migration i mappen supabase/migrations och skicka dem till projektet med supabase db push.
- Slå på Row Level Security på alla tabeller, med regler för vad alla får läsa, lägga till och ta bort.
- Kontrollerna som backenden gör idag, till exempel att namnet inte får vara tomt eller för långt, ska bli regler i databasen.
- Frontenden ska prata direkt med Supabase med paketet @supabase/supabase-js. Använd projektets adress och den publika nyckeln (publishable key). Den hemliga nyckeln får aldrig finnas i frontenden.
- Publicera frontenden på GitHub Pages med GitHub Actions.
- Läs Supabases dokumentation på https://supabase.com/docs om du är osäker på något.

Arbetssätt:
- Jobba på en ny branch. Visa först en plan med alla kommandon du tänker köra, och vänta på mitt okej.
- Behöver ett kommando databasens lösenord: be mig köra det själv i terminalen. Jag skriver aldrig lösenordet i chatten.
- När appen är publicerad: ge mig adressen, öppna en pull request och skriv i README.md hur man ändrar tabellerna och publicerar en ny version.

    Läs planen noga. Agenten kommer att skapa en mapp som heter supabase med filen config.toml och en .sql-fil per ändring av databasen. Fråga agenten vad de gör om du är nyfiken.

    KommandoVad det gör
    supabase initSkapar mappen supabase i projektet. Körs en gång.
    supabase linkKopplar mappen till ditt projekt på supabase.com. Frågar efter databasens lösenord, så det kör du själv.
    supabase migration newSkapar en ny .sql-fil för en ändring i databasen, till exempel en ny tabell.
    supabase db pushSkickar alla nya ändringar till databasen på nätet.
    supabase projects listVisar dina projekt. Bra för att kolla att du är inloggad.
    Två nycklar: vilken får synas?
    • Publishable key (börjar med sb_publishable_) är gjord för att ligga i frontenden. Alla kan se den. Det är reglerna i databasen som skyddar datan.
    • Secret key (börjar med sb_secret_) går förbi alla regler. Den får aldrig ligga i frontenden, i Git eller i chatten.

  7. 🌍 Prova på riktigt

    Öppna adressen agenten ger dig, något i stil med https://ditt-namn.github.io/fikalistan-backend/. Öppna den sedan i mobilen och be någon bredvid dig göra samma sak. Lägg till en fika. Syns den hos alla? 🎉

    Öppna Network i Dev Tools och lägg till något. Frågan går nu till /rest/v1/fikor hos supabase.co. Hittar du metoden POST och statuskoden 201?

    Öppna ditt projekt på supabase.com och klicka på Table Editor. Där ser du tabellen och raderna, precis som i del 2.

    Det fungerar inte?
    • Listan är tom fast det finns rader: reglerna i Row Level Security tillåter inte att man läser. Be agenten kontrollera reglerna.
    • 401 eller 403 i Network: fel nyckel eller en regel som stoppar. Ge felet till agenten.
    • Sidan på GitHub Pages är tom: öppna Console. Be agenten läsa felet och kontrollera att bygget får projektets adress och nyckel.
    • Inget svarar efter en tid: projektet har pausats. Starta det igen på supabase.com.

  8. 🔒 Tänk efter: vem kan använda appen?

    Nu kan vem som helst som hittar adressen lägga till och ta bort saker i din lista, om reglerna tillåter det. Det är okej för en övning, men inte för något du bryr dig om. Tre alternativ:

    • Pausa eller ta bort projektet på supabase.com när du har provat.
    • Låt det vara kvar och dela bara adressen med de du litar på.
    • Be agenten lägga till inloggning med Supabase Auth, och regler som säger att man bara får ta bort det man själv har lagt till. En bra nästa övning.
