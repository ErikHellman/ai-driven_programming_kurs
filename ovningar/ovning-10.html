⚡ Publicera på nätet

Ta appen från övning 8 ut på nätet, så att alla i fikagänget kan använda den i sina mobiler. Datan ligger redan hos Supabase. Nu får frontenden prata direkt med Supabase och publiceras gratis på GitHub Pages.

Syftet med övningen: att se hur en fullstack-app kan köra på nätet utan att du har en egen server, och att låta agenten använda ett nytt verktyg åt dig.

Innan du börjar: du behöver appen från övning 8, som fungerar på din dator, ligger på GitHub och sparar sin data hos Supabase. Supabase CLI ska vara inloggat, se guiden om Supabase.

  1. 🧩 Vad ändras?

    GitHub Pages skickar bara färdiga filer. Den kan inte köra din Express-server. Men Supabase gör automatiskt ett REST-API av varje tabell, så frontenden kan prata direkt med Supabase:

    Övning 8, på din datorÖvning 10, på nätet
    FrontendenSkickas av ExpressLigger på GitHub Pages
    FrågornaTill /api/fikor på din serverTill /rest/v1/fikor hos Supabase
    KontrollernaExpress kontrollerar datanRegler i databasen, Row Level Security
    NyckelnDen hemliga, i .env på servernDen publika, i frontenden

    Den publika nyckeln får synas för alla. Det är reglerna i databasen som bestämmer vad den får göra. Därför är reglerna det viktigaste i den här övningen.

  2. 🤖 Låt agenten göra om och publicera

    Öppna projektet i Claude- eller ChatGPT-appen och starta en ny session. Den här prompten fungerar för appen från övning 8:

    Prompt 
    Jag vill publicera den här appen på nätet, gratis. Frontenden ska ligga på GitHub Pages och prata direkt med Supabase, där datan redan finns. Supabase CLI är inloggat och projektet är länkat. Kör supabase projects list först för att kontrollera det.

Krav:
- Frontenden pratar med Supabase med paketet @supabase/supabase-js, med projektets adress och den publika nyckeln (publishable key). Den hemliga nyckeln får aldrig finnas i frontenden.
- Skriv regler med Row Level Security för vad alla får läsa, lägga till och ta bort, som en ny migration. Skicka den med supabase db push.
- Kontrollerna som Express gör idag, till exempel att namnet inte får vara tomt eller för långt, ska bli regler i databasen.
- Publicera frontenden på GitHub Pages med GitHub Actions. Projektets adress och den publika nyckeln läggs som variabler i repot.
- Läs Supabases dokumentation på https://supabase.com/docs om du är osäker på något.

Arbetssätt:
- Jobba på en ny branch. Visa först en plan med alla kommandon du tänker köra, och vänta på mitt okej.
- Behöver ett kommando databasens lösenord: be mig köra det själv i terminalen. Jag skriver aldrig lösenordet i chatten.
- När appen är publicerad: ge mig adressen, öppna en pull request och skriv i README.md hur man ändrar tabellerna och publicerar en ny version.

    Läs planen noga. Agenten kommer att lägga till en ny .sql-fil under supabase/migrations med reglerna, och ett workflow för GitHub Pages. Läs reglerna: får alla ta bort allt? Är det vad du vill?

    KommandoVad det gör
    supabase initSkapar mappen supabase i projektet. Körs en gång.
    supabase linkKopplar mappen till ditt projekt på supabase.com. Frågar efter databasens lösenord, så det kör du själv.
    supabase migration newSkapar en ny .sql-fil för en ändring i databasen, till exempel en ny tabell.
    supabase db pushSkickar alla nya ändringar till databasen på nätet.
    supabase projects listVisar dina projekt. Bra för att kolla att du är inloggad.
    Två nycklar: vilken får synas?
    • Publishable key (börjar med sb_publishable_) är gjord för att ligga i frontenden. Alla kan se den. Det är reglerna i databasen som skyddar datan.
    • Secret key (börjar med sb_secret_) går förbi alla regler. Den får aldrig ligga i frontenden, i Git eller i chatten.

  3. 🌍 Prova på riktigt

    Öppna adressen agenten ger dig, något i stil med https://ditt-namn.github.io/fikalistan-backend/. Öppna den sedan i mobilen och be någon bredvid dig göra samma sak. Lägg till en fika. Syns den hos alla? 🎉

    Öppna Network i Dev Tools och lägg till något. Frågan går nu till /rest/v1/fikor hos supabase.co. Hittar du metoden POST och statuskoden 201?

    Öppna ditt projekt på supabase.com och klicka på Table Editor. Där ser du tabellen och raderna, precis som i del 2.

    Det fungerar inte?
    • Listan är tom fast det finns rader: reglerna i Row Level Security tillåter inte att man läser. Be agenten kontrollera reglerna.
    • 401 eller 403 i Network: fel nyckel eller en regel som stoppar. Ge felet till agenten.
    • Sidan på GitHub Pages är tom: öppna Console. Be agenten läsa felet och kontrollera att bygget får projektets adress och nyckel.
    • Inget svarar efter en tid: projektet har pausats. Starta det igen på supabase.com.

  4. 🔒 Tänk efter: vem kan använda appen?

    Nu kan vem som helst som hittar adressen lägga till och ta bort saker i din lista, om reglerna tillåter det. Det är okej för en övning, men inte för något du bryr dig om. Tre alternativ:

    • Pausa eller ta bort projektet på supabase.com när du har provat.
    • Låt det vara kvar och dela bara adressen med de du litar på.
    • Be agenten lägga till inloggning med Supabase Auth, och regler som säger att man bara får ta bort det man själv har lagt till. En bra nästa övning.

Klart?

  • Jag har läst reglerna i Row Level Security och vet vad alla får göra
  • Agenten har gjort om frontenden och publicerat den på GitHub Pages via en pull request
  • Jag har sett en fråga till /rest/v1/ i Network-fliken
  • Appen fungerar i mobilen, och samma data syns hos alla
  • Jag har bestämt om projektet ska vara kvar eller tas bort
