🗺️ Ruttplaneraren

Bygg en app där du söker fram två platser, eller klickar på kartan, och får en rutt mellan dem. Den här gången finns ingen färdig prompt. Du får kraven och skriver prompten själv.

Syftet med övningen: att öva på att skriva en bra prompt för att bygga en app. Agenten kan bara bygga det du berättar om. Allt du glömmer kommer den att gissa på.

Innan du börjar: du behöver samma saker som i övning 3: Node.js, Git, ett GitHub-konto med gh inloggat och Claude- eller ChatGPT-appen. Gör gärna övning 3 först, så känner du igen stegen.

  1. Läs kraven

    Det här är vad appen ska göra och hur den ska byggas. Allt ska med i din prompt, men med dina egna ord.

    Vad appen gör:

    • Användaren väljer en startpunkt (Från) och ett mål (Till) genom att söka på en plats eller adress.
    • Användaren kan också välja Från och Till genom att klicka på kartan.
    • Appen ritar rutten mellan platserna på kartan.

    Hur den byggs:

    • En Single-Page Application som publiceras på GitHub Pages.
    • Koden sparas med Git i ett eget publikt repo på GitHub, som agenten skapar med gh.
    • React med Vite och JavaScript.
    • MapBox ritar kartan, och MapBox Directions API räknar ut rutten. Ge agenten länken till MapBox dokumentation: docs.mapbox.com.
    • Agenten ska ge dig tydliga instruktioner för allt du måste göra själv, till exempel hur du skaffar en MapBox-nyckel och hur du aktiverar GitHub Pages för appen.

    Tänk också på det du lärde dig i övning 3. Där fanns krav om API-nyckeln, base i Vite, .gitignore, mobilanpassning och svenska i gränssnittet. Behövs de här också?

  2. Förstå orden

    Du behöver inte kunna tekniken, men du behöver veta vad orden betyder för att kunna beskriva vad du vill ha.

    OrdVad det betyder
    Single-Page Application (SPA)En webbapp som består av en enda sida. När du klickar runt byter JavaScript ut innehållet i stället för att ladda en ny sida från servern. Därför kan den ligga på en enkel webbserver som GitHub Pages.
    ReactEtt JavaScript-bibliotek för att bygga gränssnitt av små återanvändbara delar, så kallade komponenter. Till exempel en sökruta, en karta och en ruta med resultatet.
    ViteVerktyget som startar utvecklingsservern på localhost och bygger ihop appen till vanliga filer som kan publiceras. Det är byggsteget från del 1.
    JavaScriptProgramspråket som körs i webbläsaren. Vi väljer det framför TypeScript för att hålla det enkelt.
    MapBoxEn tjänst för kartor. Appen hämtar kartbilderna från MapBox och ritar dem med deras bibliotek Mapbox GL JS. MapBox kan också söka fram platser utifrån namn och adresser.
    APIEtt sätt för ett program att fråga en annan tjänst om något. Appen skickar en fråga och får ett svar tillbaka, ungefär som när väderappen frågade OpenWeatherMap.
    Directions APIMapBox API för vägbeskrivningar. Appen skickar Från och Till och får tillbaka rutten som en linje att rita på kartan, plus sträcka och restid.
    TokenMapBox ord för API-nyckel. Den visar MapBox vem som frågar, så att de kan räkna hur mycket du använder.
    GitHub PagesGitHubs gratistjänst för att publicera webbsidor direkt från ett repo. Du får en adress som https://ditt-namn.github.io/ruttplaneraren/.

  3. 🔑 Skaffa en MapBox-token

    Gör det här själv, gärna innan du skriver prompten.

    1. Skapa ett konto på account.mapbox.com. Låt lösenordshanteraren skapa och spara lösenordet. Gratisnivån räcker gott för en kursapp.
    2. Logga in och öppna Access tokens. Där finns redan en Default public token som börjar med pk.. Kopiera den.
    3. Spara den i lösenordshanteraren på samma sätt som nyckeln i övning 3, till exempel som MapBox token.

    Klistra inte in token i chatten med agenten. Den ska bara finnas i lösenordshanteraren, i .env.local på din dator och i GitHub Secrets. Skriv in i prompten att agenten ska läsa den från en miljövariabel och att du lägger in den själv.

    En token som börjar med pk. är gjord för att synas i webbläsaren. När appen är publicerad kan du begränsa den till din adress på GitHub Pages under URL restrictions, så att ingen annan sida kan använda din kvot.

  4. Skriv prompten: struktur och ordning

    En bra prompt läses uppifrån och ned, precis som en beställning till en hantverkare. Börja med helheten och gå mot detaljerna. Använd rubriker och punktlistor så att inget drunknar i en lång text. Den här ordningen fungerar bra:

    DelVad den ska innehållaVarför här
    1. MålEn eller två meningar om vad du vill bygga och var. Till exempel vad det är för slags app och att den ska skapas i den här mappen.Agenten tolkar allt annat utifrån målet. Kommer det först gissar den rätt oftare.
    2. FunktionerVad användaren ska kunna göra, en punkt per sak. Skriv ur användarens perspektiv: Jag kan …Det här är kärnan. Det som inte står här blir inte byggt.
    3. TeknikVilka verktyg och tjänster som ska användas, och var appen ska publiceras.Utan det väljer agenten själv, och kanske något som inte fungerar på GitHub Pages.
    4. DokumentationLänkar till dokumentationen för tjänsterna appen använder.Agentens kunskap kan vara gammal. Med dokumentationen kan den läsa hur tjänsten fungerar i dag.
    5. HemligheterVad nyckeln heter, var den ska läsas ifrån, att den inte får hamna i Git och att du lägger in den själv.Det är lätt att glömma, och dyrt att rätta efteråt om nyckeln redan har hamnat på GitHub.
    6. Övriga kravSådant som gäller hela appen: mobil, språk, design, README, felmeddelanden när något går fel.Detaljer som är lätta att lägga till sist, men som agenten inte vet om du inte säger det.
    7. Git och GitHubAtt koden ska sparas med Git, att agenten ska skapa ett publikt repo på GitHub med gh och vad det ska heta, och att appen ska publiceras på GitHub Pages med GitHub Actions.Utan repo finns inget att publicera. Agenten skapar det inte av sig själv.
    8. Det du gör självBe agenten ge dig steg-för-steg-instruktioner för allt den inte kan göra åt dig, till exempel token och inställningar på GitHub.Då vet du vad du ska göra och när, i stället för att fastna.
    9. ArbetssättHur agenten ska jobba: visa en plan först och vänta på ditt okej, och vad den ska göra när den är klar.Står sist så att det är det sista agenten läser innan den börjar.

    Glöm inte GitHub-repot. GitHub Pages publicerar från ett repo, så projektet behöver ett eget repo på GitHub. Agenten kan skapa det åt dig med gh, men bara om du ber om det. Skriv in i prompten att agenten ska spara koden med Git, skapa ett publikt repo på ditt GitHub-konto med gh, ge det ett namn du väljer (till exempel ruttplaneraren) och pusha koden dit. Namnet blir en del av adressen: https://ditt-namn.github.io/ruttplaneraren/.

    Tips när du skriver:

    • Skriv prompten i en fil i VS Code först, till exempel prompt.md. Då kan du ändra i lugn och ro och spara den till nästa gång.
    • Var konkret. Rutten ska ritas som en tjock blå linje säger mer än visa rutten snyggt.
    • Skriv vad som ska hända när något går fel, till exempel om ingen rutt hittas eller om token saknas.
    • Titta på startprompterna i övning 3. De följer samma ordning. Men skriv din egen.
    Kolla din prompt innan du skickar den
    • Står det vad appen gör, så att någon som inte har läst kraven förstår?
    • Finns båda sätten att välja Från och Till med: sökning och klick på kartan?
    • Står det React, Vite, JavaScript och GitHub Pages?
    • Ber du agenten skapa ett publikt repo på GitHub med gh och pusha koden dit?
    • Har du med länken till MapBox dokumentation?
    • Står det var token ska ligga, och att agenten inte ska be om den i chatten?
    • Ber du agenten om instruktioner för det du måste göra själv?
    • Ber du om en plan först?

  5. Skicka prompten och granska planen

    Skapa en tom mapp, till exempel kurs/ruttplaneraren, öppna den i Claude- eller ChatGPT-appen och klistra in din prompt.

    Läs planen noga och jämför den med kraven i steg 1. Saknas något, eller har agenten valt något du inte ville? Rätta det innan du säger Kör!. Skriv också in det i din prompt.md, så blir prompten bättre till nästa gång.

  6. Gör det agenten ber dig om

    Har du skrivit prompten rätt säger agenten till när du ska göra något själv. Det här är vad som brukar behövas:

    • 🔑 Token lokalt: skapa filen .env.local i projektmappen och skriv in din token från lösenordshanteraren, under det namn agenten har valt. Be sedan agenten starta om utvecklingsservern.
    • 🔑 Token på GitHub: lägg in den i GitHub Secrets med gh secret set och namnet på variabeln, precis som i övning 3.
    • Aktivera GitHub Pages: öppna repot på GitHub, välj Settings → Pages och välj GitHub Actions under Source. Agenten kan ofta göra det åt dig med gh, men det är bra att veta var inställningen finns.

    Säger agenten inte till? Då saknades det i prompten. Fråga: Vad behöver jag göra själv för att det här ska fungera?

  7. Testa, felsök och publicera

    Testa appen på localhost. Sök fram två platser, klicka på kartan och kontrollera att rutten ritas. Öppna fliken Network i Dev Tools: där ser du frågorna till MapBox.

    Ser du något rött i Console, kopiera felet till agenten. När allt fungerar, be agenten pusha till GitHub och publicera på GitHub Pages, om den inte redan har gjort det. Öppna sedan länken i mobilen. 🎉

    Ingen karta, eller ingen rutt?
    • Grå ruta i stället för karta: token saknas eller är fel. Leta efter 401 i Network.
    • Fungerar lokalt men inte på GitHub Pages: kolla att din secret heter exakt samma sak som variabeln, och kör om bygget under Actions.
    • Slutade fungera efter URL restrictions: adressen i listan stämmer inte med adressen till appen. Lägg till http://localhost:5173 också om du vill kunna testa lokalt.

  8. Jämför med någon annan

    Visa din prompt och din app för någon bredvid dig. Vad skrev ni olika, och hur märks det i apparna? Vad skulle du lägga till i din prompt om du började om?
