🔭 Prata HTTP

Skicka egna frågor till en server och läs svaren. Ingen kod, ingen agent, bara du, terminalen och webbläsaren.

Syftet med övningen: att se HTTP med egna ögon. Metod, adress, statuskod, headers och JSON. När agenten senare bygger din backend vet du vad den pratar om.

Servern vi pratar med: JSONPlaceholder, ett gratis REST-API för att öva. Det har påhittade användare, inlägg och att göra-listor. Du kan skicka vad du vill, den låtsas spara men ändrar aldrig något på riktigt.

Windows: skriv curl.exe i stället för curl i alla kommandon nedan. I PowerShell betyder curl något annat.

  1. 📖 En GET i webbläsaren

    Öppna den här adressen i webbläsaren:

    Adress 
    https://jsonplaceholder.typicode.com/users/1

    Du ser ingen webbsida, bara JSON. Webbläsaren gjorde en GET, och servern svarade med data i stället för HTML.

    • Vad heter användare nummer 1? I vilken stad bor hen?
    • Byt 1 mot 2 i adressen. Vad händer?

  2. ⌨️ Samma fråga med curl

    Öppna terminalen och skriv:

    Terminal 
    curl https://jsonplaceholder.typicode.com/users/1

    Samma JSON, men nu i terminalen. Lägg till -i för att också se svarets första rad och headers:

    Terminal 
    curl -i https://jsonplaceholder.typicode.com/users/1
    • Vilken statuskod står på första raden?
    • Hitta headern Content-Type. Vad säger den om svaret?

  3. 🔍 Framkalla en 404

    Det finns bara tio användare. Fråga efter nummer 999:

    Terminal 
    curl -i https://jsonplaceholder.typicode.com/users/999

    Vilken statuskod får du nu, och vad står i body? Prova också en resurs som inte finns alls, till exempel /semlor.

  4. 📮 Skapa något med POST

    Nu skickar vi data till servern. -X POST väljer metoden och -d är det vi skickar i body:

    Terminal 
    curl -i -X POST https://jsonplaceholder.typicode.com/posts -d "title=Semlor till alla&userId=1"
    • Vilken statuskod fick du? Jämför med statuskoderna i del 2.
    • Vilket id fick ditt nya inlägg?
    • Hämta det nya inlägget med kommandot nedan. Finns det? Varför inte? (Läs om servern högst upp på sidan igen.)
    Terminal 
    curl -i https://jsonplaceholder.typicode.com/posts/101
    Varför inte JSON i body?

    Riktiga API:er tar oftast emot JSON, som i exemplet i del 2. Men citattecknen i JSON krånglar i terminalen, särskilt på Windows. Därför skickar vi formulärdata här. Servern förstår båda. Det är också därför agenten brukar skriva tester i stället för att testa med långa curl-kommandon.

  5. 🗑️ Ändra och ta bort

    Prova de två andra metoderna på inlägg nummer 1:

    Terminal 
    curl -i -X PUT https://jsonplaceholder.typicode.com/posts/1 -d "title=Nytt namn&userId=1"
curl -i -X DELETE https://jsonplaceholder.typicode.com/posts/1

    Vilka statuskoder får du? Vad skickar servern tillbaka i body när något tas bort?

  6. 📡 Samma sak i Network-fliken

    Nu gör vi som en frontend: frågar med fetch från JavaScript. Öppna jsonplaceholder.typicode.com, tryck F12 (eller ⌥ + ⌘ + I på Mac) och välj fliken Network. Gå sedan till Console och klistra in:

    Console 
    fetch("https://jsonplaceholder.typicode.com/users/1/todos").then((svar) => svar.json()).then(console.log)

    Tryck Enter. Gå tillbaka till Network, klicka på raden todos och titta under Headers och Response.

    • Hittar du metoden, adressen och statuskoden?
    • Hur många saker har användare 1 på sin att göra-lista?

    Vill webbläsaren inte låta dig klistra in? Skriv allow pasting i Console och tryck Enter först. Det är ett skydd mot bedragare som lurar folk att klistra in skadlig kod. Klistra bara in kod du litar på.

  7. 🧭 Gissa adresserna

    JSONPlaceholder följer REST. Resurserna heter users, posts, comments, albums, photos och todos. Gissa adressen innan du provar:

    • Alla inlägg som användare 3 har skrivit.
    • Alla kommentarer på inlägg nummer 5.
    • Album nummer 2.
    Facit
    • /users/3/posts
    • /posts/5/comments
    • /albums/2

    Gissade du rätt utan att läsa dokumentationen? Det är hela poängen med REST: adresserna blir förutsägbara.

  8. 🐙 Bonus: ett riktigt API

    GitHubs API följer också REST. Byt ditt-namn mot ditt användarnamn på GitHub:

    Terminal 
    curl https://api.github.com/users/ditt-namn
curl https://api.github.com/users/ditt-namn/repos

    Hittar du dina repon från kursen? Får du statuskoden 403 och ordet rate limit? GitHub tillåter bara 60 frågor i timmen utan inloggning, och alla i klassrummet delar samma internetadress. Ännu en statuskod att lägga på minnet.

Klart?

  • Jag har hämtat JSON med både webbläsaren och curl
  • Jag har sett statuskoderna 200, 201 och 404
  • Jag har skickat en POST, en PUT och en DELETE
  • Jag har hittat en fetch-fråga i Network-fliken och läst dess svar
  • Jag kan gissa en REST-adress utan att läsa dokumentationen

Fastnade du på ett svar? Klistra in det hos agenten och fråga: Förklara det här HTTP-svaret för mig, rad för rad.
