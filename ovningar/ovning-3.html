🚀 En riktig webbapp

Bygg en webbapp med React och Vite, samma verktyg som proffsen använder, och låt GitHub Actions bygga och publicera den åt dig.

Innan du börjar: du behöver Node.js, Git, ett GitHub-konto med gh inloggat och Claude- eller ChatGPT-appen. Kolla med node --version i terminalen. Se installationsguiderna.

Väljer du väderappen? Skapa kontot och nyckeln hos OpenWeatherMap redan före lektionen (steg 2). En ny nyckel kan ta upp till ett par timmar innan den fungerar.

  1. Välj ett projekt

    Välj det som låter roligast, eller hitta på ett eget. Varje projekt har en färdig startprompt som du kan kopiera.

    🌦️ Väderappen
    Startprompt 
    Bygg en väderapp som en webbapp i den här mappen.

Funktioner:
- Jag kan söka efter en ort och se vädret just nu och de kommande fem dagarna.
- Vädret hämtas från OpenWeatherMap. Använd deras gratis-API:er för aktuellt väder, femdygnsprognos och sökning av orter (Geocoding).
- Jag kan spara favoritorter och snabbt byta mellan dem. Favoriterna sparas i webbläsaren (localStorage).

API-nyckeln:
- Läs nyckeln från miljövariabeln VITE_OPENWEATHER_API_KEY. Skriv aldrig in den i koden.
- Skapa filen .env.example med raden VITE_OPENWEATHER_API_KEY= och se till att .env.local finns i .gitignore.
- Jag lägger själv in nyckeln i .env.local. Be mig aldrig klistra in nyckeln i chatten, och läs inte .env.local.
- Om nyckeln saknas eller inte fungerar ska appen visa ett tydligt meddelande på svenska.

Krav:
- Använd React och Vite med JavaScript. Skapa projektet direkt i den här mappen.
- Sätt base till './' i Vite-inställningarna så att appen fungerar på GitHub Pages.
- Lägg till en .gitignore som utesluter node_modules och dist.
- Sidan ska fungera lika bra på mobil som på dator: responsiv layout, knappar som är lätta att träffa med fingret och ingen sidledsscroll.
- Använd svenska i hela gränssnittet och sätt lang="sv" på sidan.
- Ge appen en tydlig titel, en favicon och en glad design med varma färger.
- Skapa en kort README.md som beskriver vad appen gör.
- När du är klar: starta utvecklingsservern och ge mig adressen.

Börja med att visa mig en kort plan. Vänta på mitt okej innan du skriver några filer.

    Väderappen kräver en API-nyckel. Följ stegen märkta 🔑 nedan. Öppna också fliken Network i Dev Tools när du söker: där ser du hur appen frågar OpenWeatherMaps server, och att nyckeln syns i adressen.

    Idéer för steg 4:

    • Ge mig ett klädtips utifrån vädret, till exempel ”ta med paraply”.

  2. 🔑 Väderappen: skaffa en API-nyckel

    En API-nyckel är en lång rad tecken som visar vem som frågar en tjänst. Tjänsten använder den för att räkna hur mycket du använder, ta betalt om du går över gratisnivån och spärra nyckeln om den missbrukas. Den som har din nyckel kan alltså använda din kvot.

    1. Skapa ett gratiskonto på openweathermap.org. Låt lösenordshanteraren skapa och spara lösenordet.
    2. Logga in och öppna API keys. Där finns redan en nyckel som heter Default. Kopiera den.
    3. Spara nyckeln i lösenordshanteraren direkt:
      • 1Password: välj New Item → API Credential, kalla den OpenWeatherMap och klistra in nyckeln under credential.
      • Proton Pass: öppna inloggningen för OpenWeatherMap, välj Edit, lägg till ett dolt fält (Hidden) som heter API-nyckel och klistra in nyckeln där.

    Klistra inte in nyckeln i chatten med agenten. Allt du skriver där skickas till AI-tjänsten. Nyckeln ska bara finnas i lösenordshanteraren, i filen .env.local på din dator och i GitHub Secrets.

    Det kan ta upp till ett par timmar innan en ny nyckel fungerar. Fram till dess svarar OpenWeatherMap med 401 i Network-fliken.

  3. Skapa en mapp och klistra in startprompten

    Skapa en tom mapp i din kursmapp, till exempel kurs/vaderappen, och öppna den i Claude- eller ChatGPT-appen precis som i övning 1. Klistra in startprompten, läs planen och svara Kör!.

    Agenten kommer vilja köra kommandon som npm install och npm run dev. Läs vad den vill göra och godkänn. Den första installationen kan ta en minut.

    Vad är node_modules? En mapp med alla paket som projektet använder, ofta tusentals filer. Den skapas av npm install och ska aldrig in i Git. Därför står den i .gitignore.

  4. 🔑 Väderappen: lägg in nyckeln i .env.local

    Agenten har skapat filen .env.example. Öppna projektmappen i VS Code, skapa en ny fil som heter .env.local bredvid den och skriv in din nyckel från lösenordshanteraren:

    .env.local 
    VITE_OPENWEATHER_API_KEY=klistra-in-din-nyckel-här

    Filen står i .gitignore, så den hamnar aldrig i Git eller på GitHub. Be sedan agenten starta om utvecklingsservern, annars läses nyckeln inte in:

    Prompt 
    Jag har lagt in nyckeln i .env.local. Starta om utvecklingsservern.

  5. Öppna appen på localhost

    När agenten är klar ger den dig en adress, oftast http://localhost:5173/. Öppna den i webbläsaren. Det är din egen dator som är servern, så bara du kan se sidan.

    Låt utvecklingsservern stå på. När agenten ändrar en fil uppdateras sidan av sig själv.

  7. Publicera med GitHub Actions

    Nu finns ett byggsteg, så GitHub måste bygga appen innan den kan publiceras. Det sköter GitHub Actions. Låt agenten ställa in allt:

    Prompt 
    Spara allt med Git och lägg upp projektet på GitHub som ett publikt repo med hjälp av gh. Skapa ett GitHub Actions-workflow som bygger appen och publicerar den på GitHub Pages, och ställ in Pages så att den använder GitHub Actions. Vänta tills bygget är klart och ge mig länken.
    🔑 Väderappen: publicera med nyckeln i GitHub Secrets

    Bygget sker på en dator hos GitHub, och den kan inte läsa din .env.local. Därför sparar du nyckeln i GitHub Secrets, ett låst fack i repot som bara GitHub Actions kan läsa. Använd den här prompten i stället:

    Prompt 
    Spara allt med Git och lägg upp projektet på GitHub som ett publikt repo med hjälp av gh. Skapa ett GitHub Actions-workflow som bygger appen och publicerar den på GitHub Pages, och ställ in Pages så att den använder GitHub Actions. Bygget ska läsa API-nyckeln från GitHub Secrets med namnet VITE_OPENWEATHER_API_KEY. Innan du pushar workflowet: säg till mig att lägga in nyckeln och vänta på mitt okej. Vänta sedan tills bygget är klart och ge mig länken.

    När agenten ber dig lägga in nyckeln, öppna en terminal i projektmappen och kör kommandot nedan. Klistra in nyckeln från lösenordshanteraren när du blir tillfrågad. Det du klistrar in syns inte.

    Alla system 
    gh secret set VITE_OPENWEATHER_API_KEY

    Eller gör det på GitHub: öppna repot, välj Settings → Secrets and variables → Actions → New repository secret, skriv namnet VITE_OPENWEATHER_API_KEY och klistra in nyckeln. Svara sedan agenten Klart!.

    En secret går inte att läsa igen, inte ens för dig. Därför finns originalet i lösenordshanteraren.

    Ärligt talat: appen körs i besökarens webbläsare, så nyckeln byggs in i appen och syns för alla i Dev Tools. Det är okej för en gratisnyckel med tak som den här. En nyckel som kostar pengar eller ger åtkomst till data måste ligga på en server. Vanan att hålla nyckeln utanför koden och Git är densamma.

    Öppna repot på GitHub och klicka på fliken Actions. En gul prick betyder att bygget pågår, en grön bock att det är klart och ett rött kryss att något gick fel. Öppna sedan länken i mobilen. 🎉

    Rött kryss eller vit sida?
    • Rött kryss i Actions: klicka på bygget, öppna steget som misslyckades och kopiera felet till agenten.
    • Vit sida på GitHub Pages: öppna Dev Tools. En 404 i Network på en JS- eller CSS-fil betyder oftast att base inte är rätt inställd. Berätta det för agenten.
    • ”API-nyckel saknas” på GitHub Pages men inte lokalt: namnet på din secret stämmer inte, eller så lades den in efter bygget. Kör om bygget under Actions med Re-run all jobs.
    • Gammal version syns: ladda om hårt med Ctrl + Shift + R, på Mac ⌘ + Shift + R.

    Gör en liten ändring, till exempel en ny färg eller en ny funktion. Be sedan agenten:

    Prompt 
    Spara ändringarna med Git och pusha dem till GitHub.

    Titta under Actions igen. GitHub bygger och publicerar den nya versionen av sig själv, varje gång du pushar.
