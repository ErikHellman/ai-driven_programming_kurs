🎫 Logga in i din app

Lägg till inloggning med GitHub i appen från övning 8 eller 10. Bara inloggade ska se listan, och man får bara ta bort det man själv har lagt till. Sedan låter du en ny session granska säkerheten.

Syftet med övningen: att se orden från del 1 i en riktig app. OAuth när du loggar in, en JWT i varje fråga, och regler i databasen som bestämmer vem som får göra vad. Du lär dig också läsa en säkerhetsgranskning.

Innan du börjar: du behöver appen från övning 8, som fungerar på din dator och ligger på GitHub. Har du gjort övning 10 fungerar den lika bra. Supabase CLI ska vara inloggat och projektet länkat, se guiden om Supabase. Ha lösenordshanteraren öppen.

  1. 🎯 Vad ska appen kunna?

    VemLäsa listanLägga tillTa bort
    Inte inloggadNej, ser bara en knapp för att logga inNejNej
    InloggadJa, allas fikorJa, i sitt eget namnBara det man själv lagt till

    Inloggningen sköts av Supabase Auth. Reglerna skrivs med Row Level Security i databasen, så att de gäller hur frågan än skickas.

  2. 🐙 Registrera appen hos GitHub

    Det här gör du själv, inte agenten. Det är ditt konto och din hemlighet.

    1. Öppna ditt projekt på supabase.com. Gå till Authentication → Sign In / Providers och klicka på GitHub. Kopiera Callback URL. Den ser ut som https://abcdefgh.supabase.co/auth/v1/callback.
    2. Öppna github.com/settings/developers, välj OAuth Apps och klicka New OAuth App.
    3. Fyll i ett namn, till exempel Fikalistan. Som Homepage URL skriver du http://localhost:3000 eller din adress på GitHub Pages. Klistra in Callback URL från Supabase i Authorization callback URL. Klicka Register application.
    4. Kopiera Client ID. Klicka sedan Generate a new client secret och spara hemligheten i lösenordshanteraren direkt. GitHub visar den bara en gång.
    5. Tillbaka i Supabase: slå på GitHub och klistra in Client ID och Client Secret. Spara.
    6. Gå till Authentication → URL Configuration. Lägg till appens adresser under Redirect URLs: http://localhost:3000/** och, om du har gjort övning 10, din adress på GitHub Pages.

    Client secret är en hemlighet. Den ska bara finnas i lösenordshanteraren och i Supabase. Aldrig i koden, i Git eller i chatten med agenten. Client ID får synas.

  3. 🤖 Låt agenten lägga till inloggningen

    Öppna projektet i Claude- eller ChatGPT-appen och starta en ny session:

    Prompt 
    Jag vill lägga till inloggning i den här appen med Supabase Auth och GitHub. GitHub är redan påslaget i Supabase, och adresserna finns under URL Configuration. Supabase CLI är inloggat och projektet är länkat. Kör supabase projects list först för att kontrollera det.

Krav:
- Den som inte är inloggad ser bara en knapp: Logga in med GitHub. Den som är inloggad ser listan, sitt namn och en knapp för att logga ut.
- Inloggningen görs i frontenden med @supabase/supabase-js och den publika nyckeln (publishable key).
- Lägg till en kolumn user_id i tabellen, som databasen fyller i själv med den inloggades id. Gör det som en ny migration och skicka den med supabase db push. Befintliga rader utan ägare får tas bort.
- Skriv regler med Row Level Security: inloggade får läsa allt, lägga till i sitt eget namn och bara ta bort sina egna rader. Den som inte är inloggad får ingenting.
- Ta bort-knappen visas bara på mina egna rader. Men det är reglerna i databasen som skyddar.
- Om appen har en Express-server: frontenden skickar med inloggningens JWT i Authorization-headern, och servern pratar med Supabase som den inloggade användaren, så att reglerna gäller även där. Den hemliga nyckeln ska inte användas för vanliga frågor.
- Läs Supabases dokumentation på https://supabase.com/docs om du är osäker på något.

Arbetssätt:
- Jobba på en ny branch. Visa först en plan och vänta på mitt okej.
- Förklara varje regel i Row Level Security i en mening på svenska.
- Be mig om hjälp om något kräver ett lösenord eller en hemlighet. Jag skriver aldrig hemligheter i chatten.
- När allt fungerar: öppna en pull request.

    Läs planen och sedan migrationen i pull requesten. Den viktigaste koden i hela appen är reglerna, oftast bara tio rader SQL. Stämmer agentens förklaringar med tabellen i steg 1?

    Vad betyder raderna i reglerna?
    • create policy … for select är en regel för att läsa. insert är lägga till, update är ändra och delete är ta bort.
    • to authenticated betyder att regeln bara gäller inloggade.
    • auth.uid() är id:t på den som är inloggad, hämtat ur JWT:n. auth.uid() = user_id betyder ”raden är min”.
    • using (true) betyder att regeln gäller alla rader.

  4. 🎫 Logga in och hitta din JWT

    Starta appen, eller öppna den på GitHub Pages när den är publicerad. Klicka Logga in med GitHub och godkänn. Första gången frågar GitHub om appen får se din profil. Det är OAuth.

    Öppna Dev Tools och fliken Network. Lägg till en fika och klicka på frågan. Under Request Headers finns Authorization: Bearer eyJ…. Det är din JWT. Ser du de tre delarna med punkter emellan?

    Öppna fliken Application → Local Storage. Där sparar Supabase din inloggning. Det är därför det är så viktigt att appen aldrig visar text från användare som HTML: kod som smugglas in via XSS skulle kunna läsa den.

    Öppna ditt projekt på supabase.com och gå till Authentication → Users. Där finns du nu som användare.

    Klistra inte in din JWT på webbsidor som avkodar tokens. Den är en inloggning så länge den gäller. Vill du se vad den innehåller, be agenten förklara hur du läser mittendelen på din egen dator.

  5. 🕵️ Försök ta dig förbi reglerna

    Nu provar du som en inbrottstjuv. Be agenten ge dig ett curl-kommando som hämtar listan direkt från Supabase med bara den publika nyckeln, utan inloggning. Kör det i terminalen.

    Svaret ska bli en tom lista, [], fast det finns rader i tabellen. Row Level Security svarar inte med ett fel när du inte får läsa. Du får bara inga rader.

    Be någon annan logga in i din app, eller logga in med ett annat GitHub-konto i ett privat fönster. Syns det andras fikor utan ta bort-knapp? Bra. Fråga agenten hur du kan försöka ta bort någon annans rad med curl och kontrollera att det inte går.

    Det fungerar inte?
    • Efter inloggningen hamnar du på fel sida, eller på localhost: appens adress saknas under URL Configuration i Supabase.
    • GitHub säger ”redirect_uri is not associated”: callback-adressen hos GitHub stämmer inte exakt med den Supabase visar.
    • Listan är tom även när du är inloggad: regeln för att läsa saknas eller är fel. Be agenten kontrollera reglerna.
    • Du kan ta bort andras fikor: regeln för att ta bort jämför inte auth.uid() med user_id, eller så använder servern den hemliga nyckeln. Ge det till agenten.

  6. 🔍 Säkerhetsgranskning i en ny session

    Starta en ny session på samma branch. I Claude Code skriver du /security-review. I Codex eller appen använder du den här prompten:

    Prompt 
    Granska ändringarna på den här branchen ur ett säkerhetsperspektiv, jämfört med main. Gå igenom inloggning, reglerna i Row Level Security, kontroll av indata, XSS, CORS, hemligheter i koden och begränsning av antal försök. Skriv en lista med problem, hur allvarliga de är och hur vi åtgärdar dem, med de allvarligaste först. Beskriv för varje problem hur någon skulle kunna utnyttja det. Ändra inget än.

    Läs listan. Rätta det som är allvarligt i samma pull request, i samma session eller en ny. Spara det som är lågt prioriterat som en idé i README.md. Är du osäker på ett problem: fråga agenten hur någon skulle kunna utnyttja det steg för steg.

    Granska pull requesten själv på GitHub, och slå ihop den när du är nöjd.

Klart?

  • Jag har registrerat appen hos GitHub och sparat client secret i lösenordshanteraren
  • Jag kan logga in med GitHub, och den som inte är inloggad ser inga fikor
  • Jag har läst reglerna i Row Level Security och förstår vad varje regel gör
  • Jag har hittat min JWT i Network-fliken
  • Jag har sett att curl utan inloggning ger en tom lista
  • En ny session har gjort en säkerhetsgranskning, och de allvarliga problemen är rättade
