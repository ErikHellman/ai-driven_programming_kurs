Verktyg, MCP och din egen app

Vad hände egentligen när agenten läste skolmaten? Och hur ger du din egen app samma förmåga?

🛠️ Tool calling 🔌 MCP 🧩 LLM i din app
  • Ungefär 60 minuter. Del 1 visade vad som går att göra. Nu förklarar vi hur, så att deltagarna kan bygga det själva.
Där vi är

En LLM kan bara skriva text

🚫

Den surfar inte

Modellen kan inte öppna skolmat.se. Den har ingen webbläsare, inget nätverk, ingen hårddisk.

✍️

Den ber om hjälp

Den skriver en begäran: ”hämta den här sidan åt mig”.

🤝

Programmet gör jobbet

Claude Code, Claude-appen eller din app utför begäran och skickar tillbaka svaret.

Det kallas tool calling, att anropa verktyg.

  • Det här sa vi redan i tillfälle 1: modellen kör aldrig något själv, harnesset gör det. Idag tittar vi på hur begäran ser ut.
  • Liknelse: modellen är en kock som sitter i telefon. Den kan säga ”hämta mjölken i kylen”, men någon annan måste gå dit.

Varje pil är ett anrop över nätet. Loopen från tillfälle 1, sedd utifrån.

  • Det är din app som är harnesset här. Den skickar frågan, tar emot begäran, kör verktyget och skickar tillbaka svaret, om och om igen tills modellen svarar med vanlig text.
  • Varje varv skickas hela samtalet igen, inklusive verktygens svar. Det är därför kontexten växer och varje varv kostar pengar.
Tool calling · Steg 1

Du beskriver verktyget

I anropet till Claude 
tools: [{
  name: "hamta_skolmat",
  description: "Hämtar skolans lunchmeny
    för en vecka. Svarar med en rätt per dag.",
  input_schema: {
    type: "object",
    properties: {
      skola: { type: "string" },
      vecka: { type: "integer" }
    },
    required: ["skola", "vecka"]
  }
}]
  • name: vad verktyget heter
  • description: när och varför modellen ska använda det
  • input_schema: vilka uppgifter den måste skicka med, som JSON
  • Ingen kod här. Bara en beskrivning
  • Formatet heter JSON Schema och är samma hos Anthropic och OpenAI, nästan ord för ord. Där heter det parameters i stället för input_schema.
  • Beskrivningen hamnar i kontexten, precis som verktygsdefinitionerna i Claude Code från tillfälle 1.
Tool calling · Steg 2 och 3

Modellen ber, din kod svarar

Claude svarar
stop_reason: "tool_use"
content: [{
  type: "tool_use",
  id: "toolu_01A",
  name: "hamta_skolmat",
  input: { skola: "Ekskolan", vecka: 48 }
}]
Din app skickar tillbaka
content: [{
  type: "tool_result",
  tool_use_id: "toolu_01A",
  content: "Mån: Fiskgratäng
    Tis: Kycklinggryta …"
}]

Mellan de två rutorna kör din kod: en fetch, en fråga till Supabase, vad som helst.

  • stop_reason "tool_use" betyder: jag är inte klar, jag väntar på ett verktyg. När modellen är klar står det "end_turn".
  • id:t kopplar ihop svaret med begäran. Modellen kan be om flera verktyg på en gång.
  • Det är vanlig JavaScript i servern från tillfälle 3. Inget magiskt.
Tool calling

Beskrivningen är allt

😶

Vag

"Hämtar data."
Modellen vet inte när verktyget behövs, eller vad den får tillbaka.

🎯

Tydlig

"Hämtar skolans lunchmeny för en vecka. Använd innan du föreslår middagar."

  • Modellen väljer verktyg enbart utifrån namn och beskrivning
  • Skriv som till en ny kollega: vad gör det, när ska det användas, vad kommer tillbaka
  • Samma lärdom som om prompter: modellen gissar det du inte skrev.
  • Be agenten skriva beskrivningarna åt dig, och läs dem. Det är den viktigaste texten i en app med verktyg.
Tool calling

Du bestämmer vad verktyget får göra

📖

Läsa

Hämta en meny, söka recept. Ofarligt, kan få köras direkt.

✏️

Ändra

Spara en plan, lägga till i listan. Kontrollera vem användaren är.

💳

Kostar eller syns

Beställa, betala, skicka mejl. Låt en människa godkänna.

Modellen kan bli lurad. Verktyget är där du sätter gränsen.

  • Samma tre nivåer som för agentens behörigheter i tillfälle 4.
  • Kontrollera alltid input i din kod: är skolan en riktig skola, är veckan ett rimligt tal. Modellen är en klient, och vi litar aldrig på klienten.
2

MCP

Ett gemensamt uttag för verktyg

MCP

Problemet: alla måste bygga allt

🔌

Utan en standard

Claude-appen, Claude Code, Codex och Cursor bygger var sin koppling till GitHub, Supabase, Figma …

🔋

Med MCP

GitHub bygger en MCP-server. Alla appar som kan MCP kan använda den.

MCP, Model Context Protocol, är som USB-C för AI. Ett uttag, många prylar.

  • Anthropic släppte MCP som öppen standard i slutet av 2024. Nu stöds det av i stort sett alla AI-verktyg, även OpenAIs.
  • Före USB fanns en sorts kabel per skrivare, mus och kamera. Samma problem, samma lösning.

  • Klienten frågar servern vilka verktyg den har, och lägger in beskrivningarna i kontexten
  • När modellen ber om ett verktyg skickar klienten vidare begäran till servern
  • Det är exakt tool calling från förra avsnittet. MCP standardiserar bara hur klienten hittar och anropar verktygen.
  • En MCP-server kan också erbjuda resurser (filer, data) och färdiga prompter, men verktygen är det man använder mest.
MCP

Lokal eller på nätet

💻

Lokal server

Ett program som klienten startar på din dator, ofta med npx. Når dina filer och din webbläsare. Exempel: Playwright.

☁️

Fjärrserver

En adress på nätet. Du loggar in hos tjänsten, ofta med OAuth som i tillfälle 4. Exempel: GitHub, Supabase, Figma.

I Claude-appen heter de connectors. Samma sak, finare namn.

  • Lokala servrar pratar med klienten via stdio, alltså in- och utdata som i terminalen. Fjärrservrar pratar HTTP.
  • Claude in Chrome från del 1 är också ett verktyg som kopplas in på samma sätt.
MCP · Lägg till en server

En webbläsare via MCP

Claude Code 
claude mcp add playwright -- npx @playwright/mcp@latest
Codex 
codex mcp add playwright -- npx @playwright/mcp@latest
  • Startar en egen Chromium i bakgrunden, utan dina inloggningar
  • Kör JavaScript, så skolmat.se fungerar
  • Claude-appen: Settings → Connectors → lägg till en egen connector med adressen till en fjärrserver
  • Kolla vad som är inkopplat: /mcp
  • Visa live: lägg till Playwright, starta om sessionen, skriv /mcp och visa verktygen (browser_navigate, browser_snapshot och så vidare).
  • Kör middagsprompten igen med ”Använd Playwright för att läsa skolmat.se”. Samma resultat som med Chrome, men med en webbläsare som inte är din egen.
  • Fjärrservrar läggs till med claude mcp add --transport http namn adress.
MCP · Säkerhet

En MCP-server är kod du litar på

  • 🏷️Välj kända servrar, från tjänsten själv eller från listan i appen. Precis som med npm-paket
  • 🪤Verktygens svar kan innehålla promptinjektion. En webbsida eller ett issue kan ge order
  • 🧠Varje server tar plats i kontexten. Slå bara på de du behöver just nu
  • ✋Läs vad den vill göra innan du godkänner. Samma regel som för agenten
  • En lokal MCP-server körs med dina rättigheter på din dator. En elak server kan göra vad som helst.
  • Farligast är kombinationen: ett verktyg som läser text utifrån, ett som når hemligheter och ett som kan skicka saker ut. Då kan en injektion läcka data.

Din egen app

Fyra regler från kursen

🔑NyckelnAPI-nyckeln bor på servern, i .env. Aldrig i frontenden. Som i tillfälle 2.
🪪InloggningBara inloggade får använda LLM:en. Varje anrop kostar pengar. Som i tillfälle 4.
🚦GränserHögst ett visst antal anrop per användare och dag, och en utgiftsgräns hos leverantören.
🪤InjektionAnvändarens text och webbsidors text är data, inte order. Verktygen sätter gränsen.
  • Utgiftsgränsen sätts i konsolen hos leverantören, till exempel platform.claude.com. Gör det innan appen publiceras.
  • Promptinjektion i egen app: en användare kan skriva ”ignorera dina instruktioner”. Om modellen bara har ofarliga verktyg spelar det mindre roll.
