Verktyg, MCP och din egen app

Vad hände egentligen när agenten läste skolmaten? Och hur ger du din egen app samma förmåga?

🛠️ Tool calling 🔌 MCP 📦 Eget paket 🧩 LLM i din app
  • Ungefär 60 minuter. Del 1 visade vad som går att göra. Nu förklarar vi hur, så att deltagarna kan bygga det själva.
Där vi är

En LLM kan bara skriva text

🚫

Den surfar inte

Modellen kan inte öppna skolmat.se. Den har ingen webbläsare, inget nätverk, ingen hårddisk.

✍️

Den ber om hjälp

Den skriver en begäran: ”hämta den här sidan åt mig”.

🤝

Programmet gör jobbet

Claude Code, Claude-appen eller din app utför begäran och skickar tillbaka svaret.

Det kallas tool calling, att anropa verktyg.

  • Det här sa vi redan i tillfälle 1: modellen kör aldrig något själv, harnesset gör det. Idag tittar vi på hur begäran ser ut.
  • Liknelse: modellen är en kock som sitter i telefon. Den kan säga ”hämta mjölken i kylen”, men någon annan måste gå dit.

Varje pil är ett anrop över nätet. Loopen från tillfälle 1, sedd utifrån.

  • Det är din app som är harnesset här. Den skickar frågan, tar emot begäran, kör verktyget och skickar tillbaka svaret, om och om igen tills modellen svarar med vanlig text.

Tool calling · Steg 1

Du beskriver verktyget

I anropet till Claude 
tools: [{
  name: "hamta_skolmat",
  description: "Hämtar skolans lunchmeny
    för en vecka. Svarar med en rätt per dag.",
  input_schema: {
    type: "object",
    properties: {
      skola: { type: "string" },
      vecka: { type: "integer" }
    },
    required: ["skola", "vecka"]
  }
}]
  • name: vad verktyget heter
  • description: när och varför modellen ska använda det
  • input_schema: vilka uppgifter den måste skicka med, som JSON
  • Ingen kod här. Bara en beskrivning
  • Formatet heter JSON Schema och är samma hos Anthropic och OpenAI, nästan ord för ord. Där heter det parameters i stället för input_schema.
  • Beskrivningen hamnar i kontexten, precis som verktygsdefinitionerna i Claude Code från tillfälle 1.
Tool calling · Steg 2 och 3

Modellen ber, din kod svarar

Claude svarar
stop_reason: "tool_use"
content: [{
  type: "tool_use",
  id: "toolu_01A",
  name: "hamta_skolmat",
  input: { skola: "Ekskolan", vecka: 48 }
}]
Din app skickar tillbaka
content: [{
  type: "tool_result",
  tool_use_id: "toolu_01A",
  content: "Mån: Fiskgratäng
    Tis: Kycklinggryta …"
}]

Mellan de två rutorna kör din kod: en fetch, en fråga till Supabase, vad som helst.

  • stop_reason "tool_use" betyder: jag är inte klar, jag väntar på ett verktyg. När modellen är klar står det "end_turn".
  • id:t kopplar ihop svaret med begäran. Modellen kan be om flera verktyg på en gång.
  • Det är vanlig JavaScript i servern från tillfälle 3. Inget magiskt.
Tool calling

Beskrivningen är allt

😶

Vag

"Hämtar data."
Modellen vet inte när verktyget behövs, eller vad den får tillbaka.

🎯

Tydlig

"Hämtar skolans lunchmeny för en vecka. Använd innan du föreslår middagar."

  • Modellen väljer verktyg enbart utifrån namn och beskrivning
  • Skriv som till en ny kollega: vad gör det, när ska det användas, vad kommer tillbaka
  • Samma lärdom som om prompter: modellen gissar det du inte skrev.
  • Be agenten skriva beskrivningarna åt dig, och läs dem. Det är den viktigaste texten i en app med verktyg.
Tool calling

Du bestämmer vad verktyget får göra

📖

Läsa

Hämta en meny, söka recept. Ofarligt, kan få köras direkt.

✏️

Ändra

Spara en plan, lägga till i listan. Kontrollera vem användaren är.

💳

Kostar eller syns

Beställa, betala, skicka mejl. Låt en människa godkänna.

Modellen kan bli lurad. Verktyget är där du sätter gränsen.

  • Samma tre nivåer som för agentens behörigheter i tillfälle 4.
  • Kontrollera alltid input i din kod: är skolan en riktig skola, är veckan ett rimligt tal. Modellen är en klient, och vi litar aldrig på klienten.

MCP

Ett gemensamt uttag för verktyg

MCP

Problemet: alla måste bygga allt

🔌

Utan en standard

Claude-appen, Claude Code, Codex och Cursor bygger var sin koppling till GitHub, Supabase, Figma …

🔋

Med MCP

GitHub bygger en MCP-server. Alla appar som kan MCP kan använda den.

MCP, Model Context Protocol, är som USB-C för AI. Ett uttag, många prylar.

  • Anthropic släppte MCP som öppen standard i slutet av 2024. Nu stöds det av i stort sett alla AI-verktyg, även OpenAIs.
  • Före USB fanns en sorts kabel per skrivare, mus och kamera. Samma problem, samma lösning.
MCP

Klient och server

✳️ KlientenClaude-appen,
Claude Code, Codex

🔌 MCP”vilka verktyg har du?”
”kör det här”

🧰 ServernPlaywright, GitHub,
Supabase …
  • Klienten frågar servern vilka verktyg den har, och lägger in beskrivningarna i kontexten
  • När modellen ber om ett verktyg skickar klienten vidare begäran till servern
  • Det är exakt tool calling från förra avsnittet. MCP standardiserar bara hur klienten hittar och anropar verktygen.
  • En MCP-server kan också erbjuda resurser (filer, data) och färdiga prompter, men verktygen är det man använder mest.
MCP

Lokal eller på nätet

💻

Lokal server

Ett program som klienten startar på din dator, ofta med npx. Når dina filer och din webbläsare. Exempel: Playwright.

☁️

Fjärrserver

En adress på nätet. Du loggar in hos tjänsten, ofta med OAuth som i tillfälle 4. Exempel: GitHub, Supabase, Figma.

I Claude-appen heter de connectors. Samma sak, finare namn.

  • Lokala servrar pratar med klienten via stdio, alltså in- och utdata som i terminalen. Fjärrservrar pratar HTTP.
  • Claude in Chrome från del 1 är också ett verktyg som kopplas in på samma sätt.
MCP · Lägg till en server

En webbläsare via MCP

Claude Code 
claude mcp add playwright -- npx @playwright/mcp@latest
Codex 
codex mcp add playwright -- npx @playwright/mcp@latest
  • Startar en egen Chromium i bakgrunden, utan dina inloggningar
  • Kör JavaScript, så skolmat.se fungerar
  • Claude-appen: Settings → Connectors → lägg till en egen connector med adressen till en fjärrserver
  • Kolla vad som är inkopplat: /mcp
  • Visa live: lägg till Playwright, starta om sessionen, skriv /mcp och visa verktygen (browser_navigate, browser_snapshot och så vidare).
  • Kör middagsprompten igen med ”Använd Playwright för att läsa skolmat.se”. Samma resultat som med Chrome, men med en webbläsare som inte är din egen.
  • Fjärrservrar läggs till med claude mcp add --transport http namn adress.
MCP · Säkerhet

En MCP-server är kod du litar på

  • 🏷️Välj kända servrar, från tjänsten själv eller från listan i appen. Precis som med npm-paket
  • 🪤Verktygens svar kan innehålla promptinjektion. En webbsida eller ett issue kan ge order
  • 🧠Varje server tar plats i kontexten. Slå bara på de du behöver just nu
  • ✋Läs vad den vill göra innan du godkänner. Samma regel som för agenten
  • En lokal MCP-server körs med dina rättigheter på din dator. En elak server kan göra vad som helst.
  • Farligast är kombinationen: ett verktyg som läser text utifrån, ett som når hemligheter och ett som kan skicka saker ut. Då kan en injektion läcka data.

Ett eget verktyg: skolmat

Reverse engineering, en klient, ett CLI och en skill

Eget verktyg

Webbläsaren är en omväg

🐢

Med Chrome varje vecka

Öppna sidan, vänta, läsa, skrolla, klicka. Många varv i loopen och mycket text i kontexten. Långsamt och dyrt.

⚡

Med ett eget kommando

skolmat meny --vecka 48 ger menyn direkt. Ett varv, lite text, samma svar varje gång.

Sidan hämtar menyn från någonstans. Den adressen kan vi använda själva.

  • Minns del 1: skolmat.se byggs i webbläsaren. Det betyder att JavaScript hämtar menyn från ett API, precis som vår egen app hämtar fikorna från Supabase.
  • CLI betyder command line interface: ett program man kör i terminalen. git, gh och npm är CLI:er.
Reverse engineering

Ta isär för att förstå

  • 🔍Reverse engineering: lista ut hur något fungerar genom att titta utifrån, utan ritningen
  • 🌐Sidan är publik, men API:et bakom är odokumenterat
  • 🛠️Webbläsaren visar varje fråga sidan skickar: vår ritning
🧰

Verktyget har du redan

Dev Tools och Network-fliken, från tillfälle 2 och 4.

  • Liknelse: som att smaka på en kaka och lista ut receptet.
  • Ordet låter avancerat, men på webben är det mest att titta noga. Allt sidan hämtar till din webbläsare kan du också se.
  • Skilj på publikt och hemligt: vi tittar bara på det sidan ändå visar för alla, utan inloggning.
Reverse engineering · Steg för steg

Hitta API:et i Network-fliken

🛠️Öppnaskolmat.se i Chrome, F12, fliken Network och filtret Fetch/XHR.
🏫KlickaVälj län, kommun och skola. Titta vilka frågor som dyker upp.
📦LetaKlicka på frågorna. Under Response: vilken av dem innehåller menyn som JSON?
📋KopieraHögerklick → Copy → Copy as cURL. Klistra in i en fil åt agenten.

Eller låt agenten göra det: med Chrome eller Playwright kan den själv läsa vilka frågor sidan skickar.

  • Gör det här live. Det brukar vara några frågor: en för listan med kommuner, en för skolorna, en för menyn. Läs adresserna högt och se vad som ändras när man byter vecka eller skola.
  • Kör den kopierade curl-frågan i terminalen. Kommer samma JSON tillbaka? Då behövs ingen webbläsare.
  • Klistra inte in cookies från en inloggad sida i en fil åt agenten. Här behövs ingen inloggning.

Reverse engineering · Var schysst

Ett odokumenterat API är inte ditt

🔄

Det kan ändras

Ingen har lovat att adressen finns kvar. Räkna med att CLI:t går sönder någon gång.

🐌

Fråga lagom

En fråga per skola och vecka räcker. Spara svaret i stället för att fråga hundra gånger.

🚧

Bara det publika

Ta dig inte förbi inloggningar eller spärrar. Läs sajtens villkor.

För eget bruk är det oftast okej. Att bygga en tjänst på det är en annan sak.

  • Många sajter har ett officiellt API. Leta efter det först, ofta under ”API”, ”Utvecklare” eller ”Öppna data”.
  • Säg det tydligt: det här är för familjens veckomeny, inte för att publicera alla skolors menyer.
Eget verktyg · Två delar

Klienten först, CLI:t ovanpå

📦KlientensokSkola() och hamtaMeny(). Pratar med API:et, svarar med objekt. All logik bor här.
⌨️CLI:tEtt tunt skal runt klienten, för dig och agenten i terminalen.
🍽️Din appMiddagsappen i nästa avsnitt importerar samma klient.
🔌SenareEn MCP-server: ännu ett skal runt klienten.

Ändras API:et rättar du ett ställe, och allt fungerar igen.

  • Samma tanke som frontend och backend i tillfälle 3: dela upp så att varje del har ett jobb.
  • Klienten ska aldrig skriva ut något eller avsluta programmet. Det är CLI:ts jobb. Då kan den användas i en webbserver också.
  • Ordet klient: koden som pratar med en tjänst åt dig. Supabase-klienten från tillfälle 3 är samma sak, fast någon annan skrev den.
Eget verktyg · Prompten

Låt agenten bygga paketet

Mål: Bygg paketet skolmat i Node.js: en klient som andra
projekt kan använda, och ett CLI som använder klienten.

Sammanhang: I curl.txt finns frågan som skolmat.se skickar.
API:et saknar dokumentation.

Krav och gränser:
- Undersök först: kör frågan, förklara varje del. Vänta på ok.
- Klienten, src/klient.js: sokSkola(namn) och
  hamtaMeny({ skola, vecka }). Svarar med objekt, skriver
  aldrig ut något. Utan vecka: nästa vecka.
- CLI:t, bin/skolmat.js: skolmat sok och skolmat meny.
  Bara argument och utskrift, --json för JSON.
- Inga paket utöver Node.

Klart när: Det finns tester för klienten, package.json har
exports och bin, och README.md visar hur klienten används
i ett annat projekt och hur CLI:t används i terminalen.
  • Fem delar igen. ”Undersök först” är reverse engineering-steget: agenten förklarar API:et innan den bygger något.
  • exports i package.json säger vad andra projekt får importera. bin säger vilket kommando som installeras.
  • --json gör CLI:t bra för agenten. Text är bra för människor.

Eget verktyg · Instruktioner

Tre texter, tre läsare

📘

README.md

För människor och agenter: installera, importera, kör CLI:t.

📄

AGENTS.md

I projektet som använder klienten: ”Hämta skolmaten med paketet skolmat. Se dess README.”

📚

En skill

För agenten: när den ska köra CLI:t, och vad den gör vid fel.

Koden är halva verktyget. Instruktionerna är den andra halvan.

  • README ligger i paketet och följer med när det installeras, i node_modules/skolmat/README.md. Agenten i det andra projektet kan läsa den där.
  • Raden i AGENTS.md hindrar att agenten i middagsappen bygger en egen, sämre version av samma sak.
  • Be agenten skriva alla tre, och läs dem. Frågan att ställa: förstår en ny kollega hur man använder det här?
Eget verktyg · Skill

En skill lär agenten använda CLI:t

.claude/skills/skolmat/SKILL.md 
---
name: skolmat
description: Hämtar skolans lunchmeny
  för en vecka. Använd när någon frågar
  om skolmaten eller planerar middagar.
---

Kör `skolmat meny --skola ekskolan --json`,
med `--vecka N` för en annan vecka.
Okänd skola? Kör `skolmat sok "namn"`.
Vid fel: säg det, hitta aldrig på.
  • En skill är instruktioner i en fil, från tillfälle 1
  • Bara description ligger i kontexten. Resten läses när den behövs
  • Lägg den i ~/.claude/skills/ så fungerar den i alla projekt
  • Kodfrågor hör hemma i README. Skillen säger när och hur
  • Description fungerar som verktygsbeskrivningen i tool calling: det är den som avgör om agenten väljer skillen. Samma regel: tydligt vad, när och varför.
  • .claude/skills i projektmappen gäller bara det projektet. ~/.claude/skills gäller alla projekt på datorn.
  • Middagsprompten från del 1 kan nu använda skillen i stället för Chrome för skolmaten.

Fyra regler från kursen

🔑NyckelnAPI-nyckeln bor på servern, i .env. Aldrig i frontenden. Som i tillfälle 2.
🪪InloggningBara inloggade får använda LLM:en. Varje anrop kostar pengar. Som i tillfälle 4.

🪤InjektionAnvändarens text och webbsidors text är data, inte order. Verktygen sätter gränsen.

  • Promptinjektion i egen app: en användare kan skriva ”ignorera dina instruktioner”. Om modellen bara har ofarliga verktyg spelar det mindre roll.
