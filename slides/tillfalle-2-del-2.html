Varför?

Du är agentens ögon

  • Agenten skriver koden, men det är du som ser sidan i webbläsaren
  • ”Det funkar inte” ger agenten väldigt lite att gå på
  • Ett exakt felmeddelande ger den nästan alltid rätt spår direkt
  • Dev Tools visar det som händer bakom sidan
🔧

Dev Tools

Utvecklarverktyg som finns inbyggda i alla vanliga webbläsare. Gratis, och du kan inte förstöra något genom att titta.

  • Allt du ändrar i Dev Tools försvinner när du laddar om sidan. Det är helt ofarligt att utforska.

Network

Serverns svar i tre siffror

✅

200

OK, här är filen

♻️

304

Du har redan den, använd din sparade kopia

🔍

404

Hittas inte. Fel namn eller sökväg

💥

500

Fel på servern, inte hos dig

En 404 på GitHub Pages beror nästan alltid på en sökväg: stora och små bokstäver, eller ett / för mycket i början.

  • Siffror som börjar på 2 betyder att det gick bra, 4 att klienten bad om fel sak, 5 att servern har problem.
  • På din egen dator spelar stora och små bokstäver ofta ingen roll, men på GitHub Pages gör de det. Klassiskt fel.

Application

När gammal data ställer till det

  • Agenten ändrar hur appen sparar data, men din webbläsare har kvar datan från förra versionen
  • Symptom: konstiga rader, tomma listor eller fel som bara du får
  • Lösning: ta bort nyckeln, eller rensa allt med Storage → Clear site data
⚠️

Rensa = borta

Allt som sparats i appen försvinner när du rensar. Be agenten om en exportknapp innan, om datan är viktig.

  • Be också agenten hantera det: ”Om sparad data har ett gammalt format, gör om den till det nya i stället för att krascha.”
Vanligt problem

”Jag ser inte ändringen!”

  • 🔄Hård omladdning: Ctrl + Shift + R, på Mac ⌘ + Shift + R. Hämtar allt på nytt i stället för att använda sparade kopior
  • 🚫Disable cache i Network-fliken stänger av sparade kopior så länge Dev Tools är öppet
  • ⏳GitHub Pages tar en minut eller två. Kolla fliken Actions på GitHub
  • 💾Sparat och pushat? Det som bara finns på din dator syns inte på nätet
  • Cache betyder att webbläsaren sparar kopior av filer för att sidan ska gå snabbare. Ibland för snabbt.
Sammanfattning

Felsökning i fem steg

  • 1️⃣Ladda om hårt. Är felet kvar?
  • 2️⃣Kolla Console. Finns det något rött?
  • 3️⃣Kolla Network. Saknas någon fil?
  • 4️⃣Kolla Application. Kan gammal data ställa till det?
  • 5️⃣Berätta för agenten. Vad du gjorde, vad du väntade dig, vad som hände, och felet.
  • Agenten kan också köra webbläsaren själv, till exempel med Playwright: ”Starta appen, testa den i en webbläsare och kolla om det blir några fel i konsolen.”

Startprompten: nu med modern teknik

Bygg en väderapp som en webbapp i den här mappen.

Funktioner:
- Jag kan söka efter en ort och se vädret just nu och de kommande fem dagarna.
- Vädret hämtas från Open-Meteo, som är gratis och inte kräver någon API-nyckel.
- Jag kan spara favoritorter och snabbt byta mellan dem. Favoriterna sparas i webbläsaren (localStorage).

Krav:
- Använd React och Vite med JavaScript. Skapa projektet direkt i den här mappen.
- Sätt base till './' i Vite-inställningarna så att appen fungerar på GitHub Pages.
- Lägg till en .gitignore som utesluter node_modules och dist.
- Sidan ska fungera lika bra på mobil som på dator: responsiv layout, knappar som är lätta att träffa med fingret och ingen sidledsscroll.
- Använd svenska i hela gränssnittet och sätt lang="sv" på sidan.
- Ge appen en tydlig titel, en favicon och en glad design med varma färger.
- Skapa en kort README.md som beskriver vad appen gör.
- När du är klar: starta utvecklingsservern och ge mig adressen.

Börja med att visa mig en kort plan. Vänta på mitt okej innan du skriver några filer.
  • Jämför med övning 1: samma struktur, men nu ber vi om React och Vite i stället för ”inget byggsteg”.
  • base './' gör att sökvägarna blir relativa, samma sak som vi bad om i övning 1.
  • Agenten kommer köra npm install och npm run dev. Godkänn kommandona.

Publicera

”Spara allt med Git och lägg upp projektet på GitHub som ett publikt repo med hjälp av gh. Skapa ett GitHub Actions-workflow som bygger appen och publicerar den på GitHub Pages, och ställ in Pages så att den använder GitHub Actions. Vänta tills bygget är klart och ge mig länken.”

  • Den som får rött kryss i Actions: klicka in på bygget, kopiera felet, ge det till agenten. Samma metod som i Dev Tools.
  • Säg att vanliga felet är en vit sida på GitHub Pages: kolla Console och Network, ofta en 404 på en JS-fil på grund av base.
