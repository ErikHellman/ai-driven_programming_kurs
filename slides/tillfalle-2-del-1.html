  • En vanlig textfil med en rad per fil eller mapp
  • Git låtsas att de filerna inte finns. De följer aldrig med till GitHub

Git · branch

Branch: en gren att experimentera i

  • main är huvudgrenen, den som publiceras på GitHub Pages
  • En branch är en kopia av historiken där du kan prova något utan att röra main. Blev det bra? Merge. Blev det dåligt? Släng grenen
  • Varje ring är en commit. Main fortsätter att leva medan grenen pågår, här rättades ett stavfel under tiden.
  • Merge betyder att ändringarna från grenen läggs in i main. En pull request på GitHub är en begäran om en merge.
Git · branch

Be agenten jobba på en branch

Skapa en ny branch som heter mork-lage och lägg till ett mörkt läge i appen där. Rör inte main.
👍

Blev det bra?

”Slå ihop branchen mork-lage med main och pusha.”

🗑️

Blev det dåligt?

”Gå tillbaka till main och ta bort branchen mork-lage.”

  • Det här är det tryggaste sättet att låta agenten prova stora ändringar. Main är orörd tills du säger till.
Git · worktree

Worktree: en mapp per branch

📁 kurs/vaderappen/ main
📄 index.html
📁 src/
📁 .git/ hela historiken
📁 kurs/vaderappen-mork/ mork-lage
📄 index.html
📁 src/
🔗 .git pekar på samma repo
  • Utan worktree byter du branch i samma mapp, och filerna byts ut framför ögonen på dig
  • Med worktree har varje branch sin egen mapp. Samma repo, samma historik
  • Två agenter kan jobba samtidigt utan att skriva i varandras filer
  • Claude- och ChatGPT-apparna kan skapa worktrees åt dig när du kör flera uppgifter parallellt i samma projekt.
  • Be agenten: ”Skapa en worktree för en ny branch som heter mork-lage.”

Klient och server

Två roller

📱

Klienten

Webbläsaren på din dator eller mobil. Den frågar efter sidor, visar dem och kör appens kod.

🖥️

Servern

En dator på nätet som alltid är på. Den svarar med filer och data, och kan dela data mellan många användare.

🍽️ Som på en restaurang: du (klienten) beställer från menyn, köket (servern) lagar maten och skickar ut den. Du ser aldrig köket, bara det som kommer ut.

Klient och server

GitHub Pages är en enkel server

  • Den skickar bara färdiga filer, samma filer till alla
  • Ingen databas, ingen inloggning, ingen kod som körs på servern
  • Allt det smarta händer i webbläsaren hos den som besöker sidan
  • Gratis, snabbt och räcker långt för egna verktyg
🗂️

Statisk webbplats

Kallas så för att filerna ser likadana ut för alla besökare. Det är precis det vi publicerade i övning 1.

  • Motsatsen kallas dynamisk: servern bygger ett eget svar till varje användare, till exempel din inkorg i Gmail.

Byggstenarna · JavaScript

JavaScript: vad som händer

app.js 
// När någon klickar på knappen …
knapp.addEventListener("click", () => {
  // … lägg till en rad i listan
  lista.append("🥐 Kanelbulle");
  // … och spara den i webbläsaren
  spara();
});
  • Reagerar på klick, tangenter och tid
  • Ändrar sidan medan du tittar på den
  • Sparar data och hämtar data från andra servrar
  • Det är JS som gör en sida till en app
  • Rader som börjar med // är kommentarer: förklaringar för människor som datorn hoppar över.
  • Vi behöver inte förstå koden. Poängen är att se att det är instruktioner: när X händer, gör Y.

Vad kan en webbapp?

Och vad kan den inte?

Möjligheter

Det här klarar webbläsaren

🖱️

Reagera

Knappar, formulär, dra och släpp, animationer och spel.

💾

Spara lokalt

Data i webbläsaren med localStorage, finns kvar när du laddar om.

🌦️

Hämta data

Fråga andra servrar via ett API, till exempel väder eller kollektivtrafik.

📷

Använda mobilen

Kamera, plats och notiser, om användaren säger ja.

📲

Installeras

Läggas på hemskärmen och fungera utan nät, en så kallad PWA.

📄

Filer

Läsa en fil du väljer, och skapa filer som du laddar ner.

  • API betyder ungefär ”ett sätt för program att prata med varandra”. En väder-API svarar med väderdata i stället för en webbsida.
  • PWA: Progressive Web App. Ser ut som en vanlig app på mobilen men är en webbsida.
Begränsningar

Datan bor i webbläsaren

💻

Datorn

localStorage🥛 Mjölk
🍞 Bröd
🧀 Ost
🚫ingen koppling
📱

Mobilen

localStorageTom lista

Samma app, samma adress, men varje webbläsare har sin egen låda. Inköpslistan på datorn syns inte i mobilen.

  • Visa gärna live: öppna din app från övning 1 på datorn och i mobilen. Lägg till något på datorn, ladda om i mobilen. Ingenting.
  • Samma sak gäller en annan webbläsare på samma dator, och privat läge.
  • Rensar du webbläsarens data försvinner listan. localStorage är bekvämt men inte en säker förvaring.
Begränsningar

Det här kan en webbapp inte göra själv

🔄

Dela data mellan enheter

Datorn och mobilen vet inte om varandra. Det kräver en server med en databas.

👥

Dela med andra

En gemensam lista för familjen kräver en server, och oftast inloggning.

⏰

Jobba när den är stängd

Ingen kod körs när ingen har sidan öppen. Inga påminnelser kl 07.00.

🔑

Hålla hemligheter

Alla kan läsa all kod i en webbapp. En API-nyckel i koden är en publik nyckel.

  • Lösningen på de tre första är en server. Tjänster som Supabase och Firebase ger dig en färdig databas, men det är ett större steg.
  • En enkel lösning för att flytta data: be agenten lägga till export och import till en fil.
  • Den sista är viktigast: lägg aldrig lösenord eller nycklar i en webbapp. Vi ser i del 2 att vem som helst kan titta.
Begränsningar

Fråga dig själv innan du bygger

  • 🙋Är det bara jag, på en enhet? Då räcker en webbapp med localStorage.
  • 🌍Behöver den data från nätet? Leta efter ett API. Kräver det en nyckel lär vi oss hantera den i del 2.
  • 📱Vill jag ha samma data i mobilen och på datorn? Då behövs en server, eller export och import.
  • 🔒Finns det något hemligt? Då hör det inte hemma i en webbapp.

Osäker? Fråga agenten: ”Kan det här byggas som en statisk webbapp på GitHub Pages?”

Från tre filer till ett riktigt projekt

Modern teknik

Proffsens verktyg

⚛️

Ramverk

React bygger sidan av små återanvändbara delar, så kallade komponenter. Bra när appen växer.

⚡

Byggverktyg

Vite visar appen medan du bygger och packar ihop allt till färdiga filer.

📦

Paket

npm hämtar färdiga byggblock som andra har skrivit, till exempel diagram och kartor.

Agenterna är riktigt bra på just de här verktygen, eftersom de har sett så mycket kod som använder dem.

  • Det finns många ramverk (Vue, Svelte, Angular). React är det vanligaste, därför väljer vi det.
  • npm följde med när vi installerade Node.js förra gången. Det är därför vi installerade Node.

  • Det är därför vi i övning 1 sa ”inget byggsteg”: då var filerna redan färdiga. Idag lägger vi till byggsteget.

localhost

  • npm run dev uppdaterar sidan direkt när agenten ändrar en fil. Låt det fönstret stå öppet.
